# Roadmap

This file records the intended milestones.

- MDB-001R Native Desktop Shell — Iced
- MDB-002 Abrir pasta — implemented: the toolbar opens the native directory picker, stores the selected `PathBuf` in memory as the current workspace, updates Explorer and status bar, and treats cancellation as a no-op. It does not scan, index, read, or persist workspace contents.
- MDB-003 Markdown Scanner — implemented: after a folder is selected, the app runs a read-only recursive scan outside the render flow, discovers real `.md` and `.markdown` files, ignores `.git`, `target`, and `node_modules`, reports counts and partial access errors, and renders only the discovered Markdown tree in Explorer. It does not parse Markdown contents, index SQLite, search, watch files, or read frontmatter.
- MDB-004 Collections — implemented: Markdown files are read read-only after discovery, YAML frontmatter is parsed into structured properties, titles and logical document types are resolved, normalized Collections are built with real counts, Explorer shows Files plus Collections, and selecting a Collection renders a simple real document list. It does not implement SQLite, search, schemas, editing, backlinks, graph, watcher, or advanced Table View.
- MDB-005 Table View — implemented: selecting a Collection opens a read-only database-style table built from real Markdown Documents. Title is always first, frontmatter properties become deterministic typed columns, missing/null values render safely, arrays and objects use compact display, row selection points to the real Document, and column headers provide basic ASC/DESC sorting. It does not edit Markdown, persist views, use SQLite, filter, resize columns, or open a document inspector.
- MDB-006 Document Inspector — implemented: the right Inspector is driven by the single selected Markdown document identity, renders real title, typed frontmatter properties, tags, filesystem metadata, and parser warnings, and shows an empty state when no document is selected. Table rows and Explorer files converge on the same selection, workspace changes clear selection, and Collection changes clear stale document selection. It remains read-only and does not implement editing, Markdown writes, SQLite, search, relations, graph, watcher, Git, MCP, or AI.
- MDB-007 File Watcher — implemented: the open workspace is watched recursively with `notify`, native events are debounced and normalized into core `WorkspaceEvent` values, Markdown create/modify/remove/rename/move updates Documents, Collections, Table View, Inspector, and Explorer automatically, parser warnings recover on later saves, and stale events from old workspaces are ignored. FlokinMD remains read-only and does not write Markdown, SQLite, search, relations, graph, Git, MCP, or AI.
- MDB-008 Search — implemented: the toolbar search field is real, `Ctrl+K` opens and focuses it, results appear in a compact desktop popup, keyboard navigation selects real Documents, Inspector updates through the existing single selected document identity, and watcher-driven document changes are reflected from the in-memory workspace state. The core search service queries loaded Documents only, covers title, filename, relative path, frontmatter keys/string values, and Markdown body content, applies deterministic scoring, snippets, multiple-term matching, and a 50-result initial limit. It does not implement SQLite, FTS, SQL, fuzzy search, regex, filters, saved searches, history, editing, relations, graph, Git, MCP, or AI. SQLite FTS remains a future disposable index/cache evolution.
- MDB-009 SQL Explorer — implemented: Collections are projected into a real in-memory SQLite database derived from the loaded Document Store, with deterministic safe table/column names, collision handling, standard `title`, `_path`, and `_file_name` columns, typed scalar values, JSON text for arrays/objects, NULL for missing properties, and a Schema Browser so users can discover normalized names. The SQL Explorer is a native in-app desktop view with a multiline monospace editor, `Executar`, `Ctrl+Enter`, result grid, row/time/truncation metadata, friendly SQL errors, and read-only single-statement enforcement for SELECT/WITH-style queries. Watcher updates, reindex, and workspace changes rebuild or invalidate the disposable projection from in-memory Documents; no `.db` file is created and Markdown remains the only source of truth. It does not implement write mode, persisted SQLite, FTS, autocomplete, relations, saved queries, query history, Git, MCP, or AI.
- MDB-010 SQL Autocomplete — deferred/post-v0.1: autocomplete is not active in the SQL Editor runtime for v0.1. The SQL Editor remains a plain multiline editor with `Ctrl+Enter` execution/review. Any completion UI, popup, keyboard navigation, ranking, and suggestion insertion are deferred until after v0.1.
- MDB-011 Relations — implemented: frontmatter wikilinks such as `project: "[[CARF]]"`, `owner: "[[Sergio]]"`, and array items like `participants: ["[[Sergio]]", "[[Maria]]"]` are interpreted as explicit document relations while ordinary strings remain ordinary strings. `flokin-core` now builds a disposable `RelationIndex` from the loaded Document Store, with outgoing and incoming lookups, relation type from property name, exact title resolution, relative-path resolution precedence for targets like `[[projects/carf.md]]`, optional display labels via `[[path|Label]]`, structured Resolved/Unresolved/Ambiguous statuses, deterministic duplicate-title handling, and no arbitrary target choice. The Inspector shows `RELAÇÕES` and `REFERENCIADO POR` sections with clickable resolved targets and visible unresolved/ambiguous states; watcher updates rebuild the index so changed relation values, created/removed targets, and title changes are reflected without manual reindex. Table View renders simple resolved wikilink values legibly while preserving row selection, and SQL projection/search semantics remain unchanged. It does not implement Graph, a full Backlinks workspace, relation editing, Markdown write-back, foreign keys, relation schema, cascade behavior, autocomplete, AI, or MCP.
- MDB-011A Real Document Viewer + Metadata Polish — implemented: selecting a real Markdown document now renders a read-only source view from the in-memory `Document` source text, including frontmatter, line numbers, monospace typography, vertical and horizontal scroll, compact real header, empty/read-error states, and no filesystem reread during rendering. Watcher updates replace the selected document content automatically, relation navigation and incoming-reference navigation update the same central viewer and Inspector, legacy demo content and future-feature document tabs were removed, and metadata timestamps now render as `dd/mm/yyyy hh:mm` with file sizes in B/KB/MB. It does not add editing, save, rendered Markdown preview, Graph, Backlinks workspace, Attachments, History, syntax highlighting, AI, or MCP.
- MDB-012 Real Markdown Editor & Tabs — implemented: selecting a real Markdown file opens a real path-keyed editor tab, duplicate opens activate the existing tab, multiple tabs keep insertion order, the active tab drives the selected document/Inspector/breadcrumb, and the center pane is now an editable multiline monospace Markdown editor backed by the loaded `Document.source_content`. Tabs track `buffer`, `saved_content`, dirty state, save errors, and external-change conflicts; dirty tabs show a visible indicator and close/window/workspace changes ask for confirmation. `Ctrl+S` and the Save toolbar action use the same safe write path, writing the same Markdown file through a temporary file plus rename, then sending the changed path through the watcher/parser pipeline so Collections, Inspector, Relations, Search, and SQL projection converge from Markdown. Clean open tabs adopt watcher updates automatically, dirty tabs preserve local buffers and expose reload/keep actions. It does not implement WYSIWYG, rendered Markdown preview, Graph, History, Git, autosave, cloud sync, AI, or MCP.
- MDB-012B Markdown Preview — implemented: each Markdown tab now supports `Editar`, `Dividido`, and `Prévia` view modes stored per tab in memory, with Edit remaining the default and preserving the existing editor, dirty state, save flow, watcher serialization, and conflict protection. Preview uses `iced::widget::markdown` with Markdown/highlighter features enabled, parses from the current live editor buffer rather than saved disk content, strips root YAML frontmatter through the scanner-owned helper, caches parsed markdown items per document path, and refreshes on typing, clean watcher updates, editor reload, and tab activation. Split mode renders editor and preview side by side with a per-tab 50/50 ratio that can be adjusted in memory. It does not implement WYSIWYG, synchronized scrolling, unsafe external link opening, relative image resolution, Mermaid, math, live HTML, source mapping, autosave, Markdown autocomplete, or Graph integration.
- MDB-013 Graph — implemented: the Activity Bar now exposes a real Grafo mode backed by a native Iced canvas. `flokin-core` derives a disposable `GraphProjection` exclusively from the current Document Store plus `RelationIndex`, preserving directed relation types and multiple semantic relations between the same source and target. Resolved relations become document-to-document edges; unresolved and ambiguous targets become non-document problem nodes without invented or arbitrary targets. The layout is deterministic, supports self-relations, cycles, disconnected components, and larger fixtures, and the app keeps user node drags only in memory. The Graph supports pan, bounded zoom, fit, focus selected, hover/selection styling, adjacent edge labels, compact document nodes, and centralized graph tokens for Dark/Light. Single click selects a Document node for the existing Inspector while staying in Graph mode; double click reuses the existing `open_or_activate_document` editor-tab flow. Watcher-driven document, title, relation, target create, and target delete updates refresh the projection without parsing dirty buffers or disturbing editor tabs. It does not implement persistence, graph filters, graph search, analytics, exports, write-back, AI, MCP, or autosave.
- MDB-013A Graph Navigation Controls + Visual Polish — implemented: Graph mode now has a compact desktop toolbar with icon controls for zoom out, zoom in, reset zoom, center selected, and fit graph, plus a live zoom percentage badge. Center selected is disabled when no Document node is selected. The toolbar, zoom badge, canvas dot grid, node shadow, and graph button states use centralized tokens. Canvas, nodes, self-loops, arrowheads, adjacent edge labels, hover state, and selected state were visually refined without changing relation projection, selection semantics, double-click open behavior, pan, wheel zoom, watcher updates, or Inspector integration.
- MDB-014 Schema — implemented: every Collection now has a read-only `SchemaCatalog` derived from the in-memory Document Store, Collections, and RelationIndex. The catalog infers String, Integer, Float, Boolean, Array, Object, Relation, Mixed, Null, and Unknown; distinguishes missing from explicit null; marks fields required only when present in every document; keeps coverage and observed type counts; treats resolved document titles as the structural `title` field; and keeps fields ordered deterministically with `title` first. Data mode now has a compact `Dados / Schema` switch for the selected Collection, rendering a dense DataGrid-style schema table and field details with minimal warnings for Mixed or explicit/observed divergence. An optional root-level `flokin.schema.yaml` is parsed read-only with `version: 1`; absent files are ignored, invalid files leave the workspace usable with inferred schema and a warning, and watcher changes reload schema without widening Markdown scanning to arbitrary YAML. It does not implement schema editing, automatic schema file generation, Database Health, validations per file, migrations, constraints, automatic fixes, SQL type enforcement, Markdown write-back, AI, or MCP.
- MDB-015 Database Health — implemented: the Activity Bar now exposes a real Saúde do banco mode backed by a GUI-independent `HealthProjection` in `flokin-core`. Health consumes parser/document diagnostics, workspace scan errors, `SchemaCatalog`, and `RelationIndex` from the current in-memory workspace, then reports structured Errors/Warnings/Info across Parsing, Schema, Relations, and Workspace categories. It detects invalid frontmatter/read or scan failures, invalid or unsupported explicit `flokin.schema.yaml`, missing required fields from explicit schema, explicit/observed type mismatches, undeclared fields when a Collection has an explicit schema, inferred Mixed types, unresolved relations, and ambiguous relations, while preserving inferred-schema fallback and avoiding false positives for self relations or cycles. The UI shows compact real counts, dense issue rows, All/Errors/Warnings filters, a local issue filter, Inspector details, and document opening through the existing editor-tab flow; watcher updates, editor saves, schema recovery, relation target create/delete, document delete, and workspace change rebuild Health without stale issues. It does not implement health scores, automatic fixes, schema editing, migrations, SQL writes, Git, AI, external lint tools, or Markdown write-back.
- MDB-016 Bulk Edit — implemented: Data mode now supports explicit multi-selection in Collection tables with a compact selection toolbar and a mandatory Bulk Edit preview flow. `flokin-core` owns GUI-independent bulk edit selection, operations, immutable plans, per-file statuses, schema-aware validation, focused frontmatter scalar patching, optimistic content fingerprints, preflight, staged batch writes, and best-effort rollback. Set/Add and Remove work for top-level scalar YAML values including String, Integer, Float, Boolean, Null, and Relation wikilinks; arrays/objects and unsafe complex YAML shapes are marked unsupported rather than rewritten. Dirty tabs and external conflicts block apply, stale previews abort the whole batch, no-op files are not rewritten, successful batches clear bulk selection, and changed paths reenter the normal watcher/Document Store/projection pipeline so Schema, Health, Relations, Graph, Search, and SQL converge from Markdown. It does not implement body bulk replace, regex, filename operations, Array/Object editing, SQL writes, persistent History/Undo, automatic Health fixes, AI, or saved operations.
- MDB-016 safety contract: selection is keyed by path and remains independent from the Inspector selection; numeric syntax is validated before planning; explicit-schema undeclared fields warn; apply rereads and fingerprints the complete changed set before staging, cleans temporary files on every failure path, and attempts rollback from captured originals after a commit failure.
- MDB-017 SQL Write Preview — implemented: SQL Explorer now has explicit Consulta and Atualizacao modes, with Consulta remaining the default read-only path. Atualizacao accepts exactly one `UPDATE` statement against a real normalized Collection table, validated structurally with `sqlparser-rs`; `INSERT`, `DELETE`, `ALTER`, `CREATE`, and `DROP` remain deferred. Preview builds a disposable in-memory SQLite projection, captures matching rows by `_path`, executes the update in a rolled-back simulation so SQLite computes WHERE and SET expressions, maps final values back to top-level Markdown frontmatter changes, and reuses the MDB-016 `BulkEditPlan` plus staged safe writer for mandatory preview, preflight, stale fingerprint aborts, dirty/conflict blocking, multi-file commit, and best-effort rollback. Supported UPDATE values are String, Integer, Float, Boolean, Null, and explicit Relation wikilinks; helper columns, `title`, Array/Object, and unsafe Mixed fields are blocked. Successful applies write Markdown only, then watcher-driven Document Store and projection rebuilds make DataGrid, Schema, Health, Relations, Graph, Search, and SQL converge from source files.
- MDB-018 History / Undo — implemented: successful Bulk Edit and SQL Update operations now persist durable local history entries only after the staged safe writer commits Markdown to disk. History is stored outside user workspaces in a versioned internal SQLite database under the platform app-data directory, isolated by canonical workspace identity, with retention of the latest 100 operations per workspace. Entries store UTC timestamps, source, PT-BR summaries, optional SQL metadata, per-file relative paths, before/after fingerprints, complete before/after content, and property diffs. The Activity Bar and Dados/Navegar menus expose a real Histórico view with compact grouped entries, detail diffs, undo availability, local storage warnings, and clear-history confirmation. Undo is an explicit previewed mutation: it blocks Undo entries, wrong workspaces, dirty tabs, external conflicts, missing/renamed files, and any current fingerprint mismatch across the whole batch; when clean, it reuses the existing BulkEditPlan preflight, staged write, commit, and rollback path to restore exact before content. Successful Undo records its own History entry and relies on the watcher to rebuild Document Store, Schema, Health, Relations, Graph, Search, and SQL. It does not implement Redo, merge conflict resolution, deleted-file restore, created-file removal, Git integration, time travel, cloud history, sync, AI, or arbitrary snapshots.
- I18N-001 Runtime Localization & Language Settings — implemented: the app now has an embedded Fluent-based localization catalog for Portuguese (Brazil) and English, a global `AppLanguage` setting in the existing versioned app settings file, OS locale detection for first run, and immediate runtime language switching through Settings without workspace reload or editor state reset. Top menus, Activity Bar labels/tooltips, Settings, Search, Explorer, Status Bar, Graph, Health, History/Undo, shell dialogs, and primary Editor/SQL/Bulk labels use translation keys with fallback coverage tests. User-authored Markdown, YAML, file paths, Collection names, field names, values, SQL text, identifiers, relation targets, document titles, and the FlokinMD brand remain untranslated.
- WORKSPACE-UX-002 Close Folder — implemented: the File menu can close the current workspace without quitting the app, reusing the existing dirty-tab protection before discarding or saving local editor buffers. Closing a folder clears only workspace-derived in-memory state, stops the watcher through the normal subscription lifecycle, returns to Welcome, and intentionally clears `last_workspace_path` so the closed workspace is not restored on the next startup. Persistent History storage is not deleted.
- ABOUT-001 About FlokinMD — implemented: the Help menu opens a global localized About panel with the official brand lockup, Cargo package version, local-first Markdown positioning, open-source note, creator credit, Flokin project line, Rust + Iced stack, and "Markdown is the database." It works with or without a workspace and does not reset editor, dirty, SQL, Graph, History, theme, or language state.
- CONTEXT-001 Context Hub — implemented: the Activity Bar exposes a localized Context view that projects the existing Markdown Document Store, deterministic semantic classification, and `RelationIndex` into a compact workspace for AI/agent/SDD Markdown artifacts. It recognizes Agents, Skills, SDD/Specs, ICE, Contexts, Prompts, Rules/Instructions, Memory, and MCP conventions from filenames/folders only, shows real counters, artifacts, incoming/outgoing relation counts, unconnected artifacts, metadata, and inspector actions to open the real document or show it in Graph. Context performs no filesystem writes, no cloud/network calls, no LLM execution, and no extra database/index; Markdown remains the source of truth and watcher refreshes flow through the normal scanner/store pipeline.
